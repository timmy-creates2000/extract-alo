## How it works (so you understand it, don't need to change it)

- **API:** `GET https://questions.aloc.com.ng/api/v2/q/<N>?subject=<slug>&year=<year>&type=utme`
  (default), or `.../m?...` with `ENDPOINT=m`. Header `AccessToken: <ALOC_API_KEY>` on every call.
- ALOC has **no pagination** — both endpoints return a *random batch* each call (`/q` ~10-20, `/m` ~40).
  The script polls each (subject, year) repeatedly and dedupes by the question's `id`, stopping when 4
  batches in a row return nothing new.
- **17 subjects × years 2001–2025** = ~400 scopes, 2 running in parallel (gentle, to stay under ALOC's rate limits).
- **Idempotent:** every question is upserted on `source_ref` (ALOC's own id, a UNIQUE column), so
  stopping and re-running **never creates duplicates** — it just re-confirms/fills gaps.
- The database already has ~1000 questions and all 17 subjects seeded. To only fill what's missing,
  run `GAPS_ONLY=1 node extract.js` instead (skips subject/years that already have questions).

### Response shape (for reference)
```json
{
  "subject": "physics", "status": 200, "total": 40,
  "data": [
    {
      "id": 554,
      "question": "Find the value of ...",
      "option": { "a": "7f", "b": "6f", "c": "15f", "d": "0.17f" },
      "answer": "d",
      "solution": "…explanation…",
      "section": "",          // comprehension passage (English), else empty
      "image": "",            // image URL if any
      "category": "…topic…",
      "examyear": "2019"
    }
  ]
}
```

### Field mapping into Supabase
| ALOC field | Supabase `question` column |
|-----------|----------------------------|
| `id` | `source_ref` (UNIQUE — dedupe key) |
| `question` | `text` |
| `option.a`–`d` | rows in `question_option` (label A–D; drop empty `e`) |
| `answer` (e.g. `"d"`) | the option with matching label gets `is_correct = true` |
| `solution` | `explanation` |
| `section` | `passage` (comprehension reading text) |
| `category` | `topic` |
| `image` | `image_key` (raw URL for now; re-hosted later) |
| `examyear` | `year` |

Skips (logged, not fatal): questions with no id, empty text, fewer than 4 options, or not exactly 1 correct answer.

The `subject`, `question`, and `question_option` tables already exist. Relevant columns:

## If you hit problems
- `429 Too Many Requests` from ALOC → the script already backs off automatically; just let it run. If it's constant, lower `CONCURRENCY` from 2 to 1 in `extract.js`.
- **Requests time out / hang (HTTP 000)** → this is our **API key's quota being exhausted**, NOT an IP
  rate-limit (confirmed: unauthenticated requests answer instantly; only requests carrying our token hang).
  A fresh IP only helps if ALOC meters per-IP-per-key. So: if the run hangs on **every** scope from the
  very start, the key quota is spent — stop, wait for it to reset (likely daily), or use a fresh/higher-tier
  key. Do NOT raise concurrency to "push through" — that does nothing against a key-quota wall.
- Try the other endpoint if one hangs: `ENDPOINT=m GAPS_ONLY=1 node extract.js` (or drop `ENDPOINT` for the default `/q`).
- `Missing env` error → a secret isn't set in the Secrets tab.
- Subjects "not seeded" error → run `node seed-subjects.js`.
- To keep it running after you close the browser tab, use Replit's **"Always On"** / deployment, or just leave the tab open until `✅ DONE`.

## Note on speed
The gentle defaults prioritize **not getting the IP rate-limited** over raw speed, because this runs
unattended in the cloud. A full sweep may take a while — that's fine, let it finish. It's better to
finish slowly in one run than to get blocked and have to wait for a cooldown.
